# Create: Netlink — Wiki

Wireless signal networks for Create: unlimited-range links, hidden bugs, a 3D keyboard, a network map, Luau scripting, limitless glue, folding walls and advanced elevators. Bundled with **Netlink: Decor**, a decoration add-on whose props react to your network.

> **Status: beta.** The mod is currently meant for **creative mode**. Recipes exist for the Netlink items, but survival balance is not final.

## 2. Core concepts

### Networks

- **Every player owns exactly one network.** Devices you place or configure join your network.
- Other players can use your network only after you authorize them with [`/network authorize <player>`](#4-commands). Authorized players can configure your devices, use keyboards bound to your network, drive your channels from the map and **edit and run your scripts**.
- A device belonging to a network you are not authorized on is **foreign**: you can see it (with HUD vision) but not change it. Foreign bugs can be ripped out.
- Most interaction needs an implanted [Netlink Terminal](#netlink-terminal).

### Channels

- A channel is a **name** on a network carrying a **signal level 0–15**.
- Names are free text up to **64 characters**. Allowed: letters, digits, space and `/ . _ - : #`; anything else is dropped. Names are **case-sensitive**. `/` is just a naming convention (`Home/Elevator/Floor1.Control`) with no special meaning, except for the outputs generated by [elevators](#advanced-elevator-pulley).
- The same name on two networks is two different channels.
- Channels have **no range limit and work across dimensions**. A device only acts while its chunk is loaded; it catches up with its channel when the chunk loads.
- A channel's level is the **strongest of all its sources**: POST devices, held keyboard keys, a pulse, a latched value (keyboard Toggle or map Hold), a keyboard pulse train, scripts and elevator outputs.

### POST and LISTEN

| Mode | What the device does |
|---|---|
| **POST** | "Sends this block's signal into the channel." The device reads redstone and feeds it into the channel. |
| **LISTEN** | "Outputs the channel's signal." The device takes the channel's level and outputs it as redstone. |

After a server start, devices wait 40 ticks (2 s) before syncing, so scripts can restore their signals first and outputs don't flicker.

## 3. Items and blocks

### Netlink Terminal

The upgrade that unlocks everything else.

- **Right-click to implant.** The item is used up; the implant stays on the player forever, including through death. There is no way to remove it. Using a second one says "A Netlink Terminal is already implanted".
- Needed for: HUD vision, the network map and `/network`, configuring links, bugs, extenders, elevators and decor props, editing keyboard binds, and scripts. Without it you get "You need an implanted Netlink Terminal".

**HUD vision**: keybind **Toggle HUD Vision**, default **H** (category *Create: Netlink*).

- Shows `NETLINK // HUD` with "*N* devices in range". Devices within **64 blocks** are drawn **through walls**.
- Looking at a device shows its type (ADVANCED LINK, BUG, WALL EXTENDER, ELEVATOR), channel (or "no channel"), POST/LISTEN, level, and `network: <owner>` or `FOREIGN - <owner>`.
- With the HUD on you can right-click **bugged blocks, Wall Extender plates and Advanced Elevator Pulleys** to configure them. These are not configurable with the HUD off.

### Advanced Redstone Link

Create's Redstone Link rebuilt on the Netlink: no frequency items, unlimited range, configured from a screen.

- Place it **against a block**, like Create's link. It pops off if that block is removed. The placer owns it.
- **Right-click** (implant needed) opens the configuration screen:
  - **Network**: "◀ My network" cycles through networks you can access.
  - **Mode**: POST / LISTEN.
  - **Channel**: a text field plus "Channels on this network". Click a channel to fill it in.
  - **Apply** / **Cancel**.
- **Sneak + right-click** switches POST ↔ LISTEN ("Mode: POST" / "Mode: LISTEN").
- **POST** reads the strongest redstone input around it and transmits it **in the same tick**. Create's link waits a tick.
- **LISTEN** outputs the channel's level as redstone to its neighbours, with strong power into the block it is attached to.

### Bug

A hidden network device you stick onto any block or mechanism. Stacks to 16.

- **Right-click any block** with a Bug to attach it. The bug is used up and, if you have an implant, its configuration screen opens. One bug per block ("This block is already bugged").
- Bugs are **invisible** unless seen through an active terminal HUD.
- **POST** bug: reports the block's signal. That is redstone dust power, a source's output, a `power`/`powered` block state, or the redstone the block receives. It updates in the same tick the block changes.
- **LISTEN** bug: powers the block as if it received redstone at the channel's level. Works for dust, repeaters, lamps, doors, pistons and Create machines alike.
- Pure signal sources (levers, buttons, torches, redstone blocks, observers…) can only **POST**: "This block only calls - POST only". Redstone dust, repeaters/comparators and Create's Elevator Contacts can LISTEN.
- If the bugged block is broken or replaced by a different block, the bug drops as an item.
- To reconfigure later: turn **HUD on** and right-click the bugged block. The screen offers **Apply**, **Detach** (returns the bug) and **Cancel**.
- A **foreign** bug shows "Someone is listening in…" and a **Rip it out** button. That destroys the bug without giving you the item, and the owner's name is shown.

### Netlink Keyboard

A full keyboard version of Create's Linked Controller: bind **any key** to a channel. Hold it in either hand.

| Action | Effect |
|---|---|
| **Right-click** (not on a link) | Toggles typing mode: "Keyboard online" / "Keyboard offline". While online, **only bound keys** are taken away from the game; everything else works normally. **Esc** or opening any screen turns it offline. |
| **Right-click an Advanced Redstone Link** | Bind mode: "Press any key to bind this link's channel to it. Esc cancels." The next key you press takes the link's channel and network ("Channel bound to [key]"). If the key already had a bind, its channel is replaced and its action is kept. |
| **Sneak + right-click** (main hand) | Opens the bind editor (implant needed). |

The **bind editor** has a **Network** selector and one row per bind: **Key** (click it, then press a key; Esc cancels), **Channel**, **Signal action**, **Ticks** and ✕ to delete. **+ Add bind** adds a row. Click a channel in "Channels - click to put into the selected bind" to fill in the focused row. **Apply** (or Enter), **Clear all**, **Cancel**. Up to **48 binds**; one key can drive several channels.

| Signal action | Behaviour |
|---|---|
| **Hold** | "Power when pressed: the channel is on while the key is held" (level 15). |
| **Toggle** | "Each press switches the channel on or off." Latches 15. Survives restarts. |
| **Pulse** | "Sends a pulse lasting the given number of ticks" (level 15). |
| **Toggle pulse** | "Starts or stops a pulse train (ticks on, ticks off)." Survives restarts. |

Ticks: 1–1200, default 10. Removing or changing a bind stops whatever it was doing: an active toggle, a pulse train or a held key.

Binding and editing need an implant and build permission (not in adventure mode). Pressing keys works for anyone who is the keyboard network's owner or authorized on it.

### Network Map

Not an item: a screen. Open it with the keybind **Open Network Map** (default **N**) or [`/network`](#4-commands). Needs an implant.

- **Title bar**: owner and authorized players, a network selector ("◀ My network" / other owners) and **{ } Scripts**, which opens the [script editor](#the-script-editor) for that network.
- **Map**: a live top-down map with faint terrain relief. Each device is drawn as the mechanism it controls. **Drag** to pan and **scroll** to zoom. Click a device to select its channel. Hovering shows details; devices in other dimensions are summarized as "+*N* in other dimensions".
- **CHANNELS** list: every channel with its level and an **IN** (POST) / **OUT** (LISTEN) strip of device icons. Hover the strip for the full list. Click to select; **double-click** to pulse.
- **Controls for the selected channel**:
  - **Pulse**: a 10-tick pulse at the chosen level.
  - **Hold**: latches the channel at the level until released. Survives restarts.
  - **Release**: removes the latch.
  - **level** picker: `-`, `+`, `15`.

The map's **Hold** and the keyboard's **Toggle** share the same latch, so a Toggle press can release a Hold and vice versa.

### Netlink Glue

Create's Super Glue without limits: any size, any distance. It makes ordinary Create glue, so contraptions and Wall Extenders treat it exactly like Super Glue. Use it in the **main hand**. It is not used up.

| Action | Effect |
|---|---|
| Right-click two corners | Corners can be on blocks **or in mid-air**, placed 4 blocks in front of you. The box shrinks to the blocks inside it. A preview shows the size; right-click to glue. |
| Sneak + right-click a block | Glues **everything connected** to it: up to 24 blocks away on each axis and 8192 blocks total. Natural terrain is skipped: dirt, stone, sand, snow, terracotta, leaves, logs and ice. |
| Left-click a glue box (red) | Removes it, along with the other pieces of the same selection. |
| Left-click / sneak + right-click while selecting | Discards the selection. |

Big selections are split into overlapping 16-block glue pieces, so Create can still find the glue far from the centre. A selection needing more than 4096 pieces is refused ("That selection is too big to glue").

### Wall Extender

Folds a glued shape into flat plates built into existing blocks. The shape slides out on a network signal and back in.

**Assembly**

1. Glue the shape with Super Glue or Netlink Glue. It needs at least 2 blocks and at most **4096**. It must contain **no block entities** (chests, signs, Create machines…).
2. Right-click the shape with a Wall Extender. The **Wall Extender - Assembly** screen opens with a live 3D preview (drag to orbit, scroll to zoom).
3. Pick the side the plates go on: **Bottom, Top, North, South, West, East**. The screen shows the shape size, number of plates and travel.
4. The plates are built **into existing blocks**: every plate spot (shown red if missing) must already be a full, solid, breakable block without a block entity or fluid. Otherwise you get "fill the *N* red plate spots with solid blocks".
5. **Fold it**. The shape collapses into the plates, the glue and one Wall Extender item are used up, and the extender joins your network.

**Use and configuration**

- The wall **extends while its channel is ON** (or while OFF with Invert) and retracts otherwise. It moves one block every *Speed* ticks: 1–100, default 4 ("ticks per block"). While it moves it stays solid and pushes entities.
- Configure it with **HUD on**: right-click any plate. The screen has **Network**, **Speed**, **Invert: off/ON**, **Channel**, **Apply**, **Remove** and **Cancel**.
- **Remove**, or breaking any plate, takes the extender apart. The wall stands back up fully extended, every plate turns back into the block it was built into, and the Wall Extender item drops. If something now occupies a wall position, that block drops as an item instead. Plates take as long to break as the block they were built into.
- If something blocks its path, the wall stops where it is.

### Advanced Elevator Pulley

Create's Elevator Pulley with a built-in Netlink device. Build the elevator exactly like a Create elevator: the pulley needs rotation, a cabin and Elevator Contacts on each floor. The pulley also announces itself on your network and can be driven by scripts.

- Placing it registers it on your network as **Elevator1**, **Elevator2**…: "Elevator registered as … - rename it with H on". With **HUD on**, right-click it with an **empty hand** (not sneaking) to set **Network** and **Name**. `/` in the name is replaced by `_`. Keep names unique per network; scripts find elevators by name.
- **Floors** are the elevator's contacts, bottom to top. A floor's **name** is the contact's short name; a contact without one is named by its position counted from **0**. Its **label** is the contact's long name.

**Network outputs** (all on the elevator's network, `<name>` = elevator name):

| Channel | Level |
|---|---|
| `<name>/Moving` | 15 while the cabin travels |
| `<name>/Up`, `<name>/Down` | 15 while travelling in that direction |
| `<name>/Target` | 1-based floor number of the target while moving (max 15) |
| `<name>/To/<floor>` | 15 while heading to that floor |
| `<name>/Floor` | 1-based floor number while standing at a floor (max 15) |
| `<name>/At/<floor>` | 15 while standing at that floor |
| `<name>/Departed` | Pulse when the cabin starts moving (length = `ArrivalPulse`, default 10 ticks) |
| `<name>/Arrived` | Pulse when the cabin stops at a floor |

A LISTEN link on `Elevator1/At/2` lights a lamp while the cabin waits at floor "2". Scripts can also change speed, acceleration and locking ([Elevator API](#elevators)). A cabin held mid-shaft by a script keeps its doors closed until it arrives.

### Elevator Panel

A floor keypad for the inside of a cabin.

- Place it on a cabin wall; it moves with the wall it hangs on. Right-clicking it outside an assembled cabin says "Put the panel inside an elevator cabin, then right-click it there".
- Inside a cabin, **right-click** the panel to focus it: "type the floor, Enter to go · RMB or Esc to let go".
  - Type up to 4 characters: digits, optionally starting with `-`. **Backspace** corrects. While focused, these keys don't reach the game.
  - **Enter** sends the cabin: "Going to …", "No floor …" or "Floor … can't be reached".
  - **Esc** or another right-click releases the panel; moving more than 8 blocks away also releases it.
- What you type is matched to a floor by **name** (case-insensitive), then by **label**, then as a **1-based number**.
- It works with any Create elevator. On an **Advanced** Elevator Pulley, a script can set `Locked` ("This elevator is locked"), and every request fires the `Requested` script event.

## 5. Scripting

Scripts are small programs written in **Luau** (Roblox's Lua dialect). They run **on the server** and drive your network: react to channels, set and pulse signals, control elevators, keep saved data and, for operators, change the world.

### The script editor

Open the Network Map (**N**) and click **{ } Scripts**. The editor works on the network shown in the map's selector, so authorized players can edit other networks' scripts.

- **Left**: the script list. **+ New** creates a script pre-filled with an annotated example; **Delete** removes the selected one. The dot next to a name shows its state:

  | Dot | State |
  |---|---|
  | green | running |
  | orange | running, but a thread hit an error |
  | grey | stopped |

- **Top**: name field (max 32 characters; letters, digits, space, `_ - .`), **▶ Run**, **■ Stop**, **Save**, and `● running` / `○ stopped`.
- **Middle**: the code editor with line numbers, syntax highlighting and suggestions. The line of the latest error is marked.
- **Bottom**: the **Console**: `print` (white), `warn` (yellow), errors (red), start/stop messages (cyan). **Clear** empties it. Scroll it with the mouse wheel.
- Closing the screen saves unsaved changes.

| Shortcut | Action |
|---|---|
| Ctrl+S | Save |
| Ctrl+Enter | Run |
| Ctrl+/ | Toggle comment |
| Ctrl+D | Duplicate line |
| Ctrl+Space | Suggestions (they also pop up after `.` and `:`) |
| Ctrl+Z / Ctrl+Y or Ctrl+Shift+Z | Undo / redo |
| Tab / Shift+Tab | Indent / outdent (whole selection if any) |
| Ctrl+A / C / X / V | Select all / copy / cut / paste |
| Ctrl+← / → | Jump by word |
| Ctrl+Backspace / Ctrl+Delete | Delete word |
| Home / Ctrl+Home / Ctrl+End | Line start / start of script / end of script |

Enter keeps the indentation and indents after block openers. Like Roblox Studio, it adds the matching `end` (or `until`) right away. Brackets and quotes are auto-paired.

### How scripts run

- **Run** saves the script, marks it enabled and (re)starts it. **Stop** stops it and marks it disabled. **Enabled scripts start automatically when the server starts.**
- A script belongs to a **network**, not to the player who wrote it. It always acts on its network's channels, elevators and storage.
- The top level of the script runs once. The script stays running until it is stopped, so handlers connected with `:Connect` keep working after the top level ends. A script doesn't need a loop.
- Every event handler and every `task.spawn` / `task.delay` runs in **its own thread**. Waiting inside a handler is fine.
- An error ends only the thread it happened in. The console shows `script:line message` and the script is marked orange; other threads and handlers keep running. Syntax errors stop the script from starting: "■ not started: fix the error and press Run again".
- **Stopping a script removes every value it set with `signal.set`.** Pulses it started run out on their own.
- The console keeps the last 300 lines (each up to 400 characters). It survives script restarts but not server restarts.

### Operators and the `world` library

- The **`world` library exists only if the network owner was an operator when the script started**. The console then shows `(operator: world library on)`. On a server this means the owner is in the ops list; in singleplayer it normally means commands (cheats) are allowed. If the owner becomes an operator later, press Run again.
- Every `world` call checks again. If the owner is no longer an operator, calls fail with "the world library needs the network owner to be an operator".
- `world.run` and the command-based functions run **with the network owner's permission level**.
- World events (`PlayerJoined`, `PlayerLeft`, `Chatted`) are delivered only to operator scripts. Every operator script on the server receives them.

> **Admins:** authorized players can edit and run scripts on your network. If you are an operator, their scripts get the `world` library and run commands with your permissions. Authorize only players you trust with that.

### Language: Luau subset

Your code is converted from Luau to Lua 5.2 (run by LuaJ) with line numbers kept, so errors point at the right line.

**Supported Luau features**

| Feature | Example |
|---|---|
| Type annotations (locals, parameters, returns, `for` variables) | `local n: number = 5`, `function f(a: string): boolean` |
| Type declarations | `type Point = {x: number, y: number}`, `export type …` |
| Casts | `value :: number` |
| Generics on functions | `function id<T>(x: T): T` |
| Compound assignment | `+= -= *= /= //= %= ^= ..=` |
| `continue` | inside `for`, `while`, `repeat` |
| String interpolation | `` `Floor {lift.Floor}` `` (escape with `\{`, `` \` ``) |
| Floor division | `a // b` (becomes `math.floor(a / b)`) |
| `if` expressions | `local s = if x > 0 then "on" else "off"` |
| Binary literals, digit separators | `0b1010`, `1_000_000` |

**Not supported**: anything else is passed through unchanged and fails or behaves as plain Lua 5.2:

- Generalized iteration (`for k, v in t do`). Use `pairs(t)` / `ipairs(t)`.
- Roblox engine APIs (`game`, `workspace`, `Instance`, `Vector3`, `CFrame`…) and the Luau-only libraries `buffer`, `vector`, `utf8`.
- `...` inside an `if` expression. It is wrapped in a function, so `...` is not available there.
- `load(...)` exists but compiles **plain Lua 5.2**, not Luau.

**Available standard library**: the Lua 5.2 base functions (`assert`, `error`, `pairs`, `ipairs`, `next`, `select`, `tostring`, `tonumber`, `type`, `rawget`/`rawset`/`rawequal`/`rawlen`, `setmetatable`/`getmetatable`, `pcall`, `xpcall`, `load`), `string` (without `string.dump`; `string.rep` results are capped at 1,000,000 characters), `table`, `math`, `bit32` and `coroutine`.
**Removed**: `dofile`, `loadfile`, `require`, `module`, `collectgarbage`, `debug`, `package`, `io`. `os` contains only `os.clock` and `os.time`.

### Limits

| Limit | Value |
|---|---|
| Scripts per network | **32** ("This network already has the maximum number of scripts") |
| Script size | 60,000 characters (longer code is cut off when saved) |
| Instructions per thread per tick | 250,000 |
| Instructions per script per tick (all threads together) | 1,000,000 |
| Threads per script (running + scheduled) | 512 (extra event handler calls are dropped) |
| `world` calls per thread per tick | 4096 |
| `task.wait` / `task.delay` | Minimum 1 tick (0.05 s), maximum 24 h |
| `signal.pulse` length | 1–1200 ticks |
| `world.fill` / `world.replace` area | 32,768 blocks |
| `world.entitiesNear` / `removeEntities` radius | 256 blocks |
| `storage` | 2000 keys per network, 65,536 characters per encoded value, tables nested up to 16 deep |

Going over an instruction limit raises `script timed out: too much work in one tick (add task.wait() in long loops)` in the thread that hit it. Any long `while true do` loop needs a `task.wait()`.

### API reference

Positions are block coordinates `x, y, z`. Times are in **seconds** unless noted as ticks (20 ticks = 1 s). `?` marks an optional argument.

#### Globals

| Function | Returns | Notes |
|---|---|---|
| `print(...)` | — | Writes to the console (arguments separated by tabs, `__tostring` respected). |
| `warn(...)` | — | Same, as a yellow warning. |
| `wait(seconds?)` | seconds waited | Alias of `task.wait`. |
| `spawn(fn, ...)` | — | Alias of `task.spawn`. |
| `delay(seconds, fn, ...)` | — | Alias of `task.delay`. |
| `tick()` | number | Real time, seconds since 1970 (with fractions). |
| `time()` | number | Seconds since this script started (game ticks / 20). |
| `os.time()` | integer | Real time, whole seconds since 1970. |
| `os.clock()` | number | High-resolution clock in seconds, for measuring durations. |
| `typeof(v)` | string | `"RBXScriptSignal"` for events, `"RBXScriptConnection"` for connections, `"Elevator"` for elevator objects, otherwise `type(v)`. |
| `pcall(f, ...)` | ok, ... | Like Lua's, with trailing whitespace trimmed from error messages. It can't catch a script being stopped. |

#### task

| Function | Returns | Notes |
|---|---|---|
| `task.wait(seconds?)` | seconds actually waited | Pauses this thread. No argument = 1 tick. |
| `task.spawn(fn, ...)` | — | Runs `fn(...)` in a new thread right away (this tick or the next). `fn` may also be a coroutine. |
| `task.defer(fn, ...)` | — | Same as `task.spawn`. |
| `task.delay(seconds, fn, ...)` | — | Runs `fn(...)` in a new thread after the delay. |

#### signal: channels of the script's network

| Function | Returns | Notes |
|---|---|---|
| `signal.get(channel)` | 0–15 | The channel's current level (strongest of all sources). |
| `signal.set(channel, value?)` | — | Makes the script a source on the channel until cleared or the script stops. `value`: number 0–15 (clamped), `true` = 15, `false` = 0, omitted = 15. Other sources still count, so `set(ch, 0)` doesn't force the channel to 0. |
| `signal.clear(channel)` | — | Stops this script driving the channel. |
| `signal.pulse(channel, ticks?, value?)` | — | Pulse of `ticks` (1–1200, default 10) at `value` (1–15, default 15). A channel has one pulse at a time, shared with keyboard and map pulses; a new pulse replaces the running one. |
| `signal.list()` | `{string}` | Sorted names of all channels on the network. |
| `signal.changed(channel)` | Event | Fires with `(value, old)` whenever the channel's level changes, whatever the cause. Pass the exact channel name. `signal.Changed` is an alias. |

An empty channel name raises `empty channel name`.

#### Events and connections

Events use the Roblox style:

| Member | Returns | Notes |
|---|---|---|
| `event:Connect(fn)` | Connection | Calls `fn(...)` (in a new thread) every time the event fires. |
| `event:Once(fn)` | Connection | Calls `fn` the next time only. |
| `event:Wait()` | the event's values | Pauses this thread until the event fires. |
| `connection.Connected` | boolean | `false` after `Disconnect`. |
| `connection:Disconnect()` | — | Stops the connection. |

#### Elevators

Advanced Elevator Pulleys on the script's network, found by the name set with the HUD.

| Function | Returns | Notes |
|---|---|---|
| `elevator.get(name)` | Elevator or `nil` | `nil` if the network has no elevator with that name. |
| `elevator.wait(name, timeout?)` | Elevator or `nil` | Checks every 0.5 s until an elevator with that name exists (e.g. placed or renamed later); returns `nil` after `timeout` seconds (waits forever without one). |
| `elevator.list()` | `{string}` | Names of the network's elevators, including ones whose chunk isn't loaded (`Assembled` is false for those). |

**Elevator properties**

| Property | Type | R/W | Meaning |
|---|---|---|---|

### Example scripts

**1. Elevator call buttons**: put an Advanced Redstone Link in POST mode on each floor's button, with channels `Lobby/Call/<floor name>`.

```lua
local lift = elevator.wait("Lobby", 30)
if not lift then
	warn("No elevator named Lobby on this network")
	return
end

while not lift.Assembled do
	task.wait(1) -- the pulley's chunk isn't loaded yet
end

for _, floor in ipairs(lift:GetFloors()) do
	signal.changed(`Lobby/Call/{floor.Name}`):Connect(function(value, old)
		if value > 0 and old == 0 then
			lift:GoTo(floor.Name)
		end
	end)
end

lift.Arrived:Connect(function(floor)
	print(`Arrived at {floor}`)
	signal.pulse("Lobby/Chime", 10)
end)
```

**2. Front door that opens for a few seconds, unless the house is locked**: the doorbell button POSTs `Home/Doorbell`, a lever POSTs `Home/Locked`, and a LISTEN link or bug on the door's mechanism reads `Home/FrontDoor`.

```lua
local OPEN_SECONDS = 4

signal.changed("Home/Doorbell"):Connect(function(value)
	if value == 0 or signal.get("Home/Locked") > 0 then
		return
	end
	signal.set("Home/FrontDoor", true)
	task.wait(OPEN_SECONDS)
	signal.clear("Home/FrontDoor")
end)
```

**3. Visitor counter with saved data**: a pressure plate POSTs `Shop/Entrance`. The count survives restarts.

```lua
print(`Visitors so far: {storage.get("visitors", 0)}`)

signal.changed("Shop/Entrance"):Connect(function(value, old)
	if value > 0 and old == 0 then
		local n = storage.increment("visitors")
		print(`Visitor #{n}`)
		-- show the last 4 bits on a channel, e.g. for a Status Monitor
		signal.set("Shop/VisitorsMod16", n % 16)
	end
end)
```

**4. Welcome message and a chat command (operators only)**

```lua
if not world then
	warn("The world library needs the network owner to be an operator")
	return
end

world.PlayerJoined:Connect(function(name)
	task.wait(2) -- let the player finish joining
	local visits = storage.increment("joins:" .. name)
	local subtitle = if visits == 1 then "First time here!" else `Visit #{visits}`
	world.title(name, "Welcome", subtitle)
	local p = world.getPlayer(name)
	if p then
		world.sound(p.X, p.Y, p.Z, "entity.player.levelup", 1, 1.2, p.Dimension)
	end
end)

world.Chatted:Connect(function(name, message)
	if message == "!day" then
		world.setTime("day")
		world.broadcast(`{name} made it day`)
	end
end)
```

## 6. Netlink: Decor

Decorations that react to your network, neon in every colour, and a voxel chisel for high-resolution sculpting. Everything is in the **Netlink: Decor** creative tab; there are no recipes.

### Blocks

| Block | Description |
|---|---|
| **Server Rack** | Full-size rack with 6 drive bays (activity and health LEDs) and a status light. *Live.* |
| **Network Switch** | Flat switch with 8 port LEDs and a status LED. *Live.* |
| **Wireless Router** | Small router with 3 LEDs. *Live.* |
| **Satellite Dish** | Dish that turns. *Live.* |
| **Antenna Mast** | Lattice mast; stack it as high as you like. The top segment carries an aviation light. *Live.* |
| **Status Monitor** | Screen showing a channel's value. *Live.* |
| **Patch Panel** | Wall-mounted panel with 12 port LEDs; placed against the face you click. *Live.* |
| **Cable Duct** | Square duct; placed along any axis, like a log. |
| **Neon** (16 colours) | Full glowing block, light level 15. White, Orange, Magenta, Light Blue, Yellow, Lime, Pink, Gray, Light Gray, Cyan, Purple, Blue, Brown, Green, Red, Black. |
| **Neon Panel** (16 colours) | Thin glowing panel that sticks to any face, light level 15. |

### Linking live props to a channel

**Sneak + right-click** a live prop with an **empty hand** (implant needed) to open **Link to a channel**: **Network**, **Channel**, **Unlink**, **Save**.

- Props only **display** a channel; they never send signals. They update every 5 ticks.
- Anyone with an implant can link an unlinked prop. A linked prop can only be changed by players allowed on its network.

| Prop | Unlinked | Linked, level 0 | Linked, level > 0 |
|---|---|---|---|
| Server Rack | drives blink at random, status light pulses cyan | drives mostly idle, status amber | drives blink faster the higher the level, status green, health LEDs flicker amber |
| Network Switch | ports blink, status green | ports mostly idle, status amber | ports busier with level, status cyan |
| Wireless Router | activity LED blinks, third LED off | third LED amber | activity faster, third LED green |
| Satellite Dish | turns slowly | stops | turns faster the higher the level |
| Antenna Mast (top) | slow red blink | slow red blink | fast white strobe |
| Status Monitor | "NO LINK" | `0` (amber) + channel name | the level (green) + channel name + bar |
| Patch Panel | ports blink at random | all ports dark | lights about level × 12 / 15 ports |

### Voxel Chisel

Sculpts any block into voxels. Hold it in the **main hand**. It has no keybinds of its own; it uses the attack and use buttons.

| Input | Action |
|---|---|
| **Left-click** (hold to repeat) | Carve |
| **Right-click** (hold to repeat) | Add or Paint, depending on the setting |
| **Sneak + right-click a block** | Pick its material ("Material: …") |
| **Sneak + right-click the air** | Open the settings |

**Material**: a block held in the **off hand** is used first; otherwise the sneak-picked block is used. Without either: "No material: hold a block in your off hand or sneak-pick one". Blocks with block entities and Voxel Sculptures can't be materials.

**Settings** (screen **Voxel Chisel**, saved on the chisel):

| Setting | Values |
|---|---|
| Resolution | 1, 2, 4, 8, 16 (default), 32, 64 voxels per block edge ("*N* per edge (*N³* voxels per block)") |
| Brush size and shape | 1–16 voxels; **Cube** or **Sphere** (sphere applies from size 3) |
| Right-click | **Add** (fills empty voxels) or **Paint** (recolours existing voxels) |

The action bar shows `Voxel Chisel · res … · brush … · Add/Paint · material`. The brush is outlined: blue = add, yellow = paint, red = carve, and a white box marks the targeted voxel.

**How sculpting works**

- Carving or painting a normal block turns it into a **Voxel Sculpture** that keeps the block's shape, so stairs keep their steps. Adding into air or replaceable blocks creates a new sculpture.
- Blocks that can be sculpted: no block entity, no fluid, breakable, with a non-empty shape.
- Mixing resolutions is fine: the block is converted to the finer one.
- Up to **255 materials** per block ("Too many materials in this block").
- A sculpture with nothing left disappears. A sculpture filled completely with one full-block material turns back into that block.
- A sculpture glows with the brightest light of its materials.
- One stroke reaches at most **64 blocks**. You must be within 10 blocks and allowed to build there.
- **Breaking** a sculpture in survival drops a **Voxel Sculpture** item that keeps its shape. **Pick block** (middle-click) gives a copy in creative. Placing the item puts the sculpture back. The item is not in the creative tab.
- Sculptures store their facing and mirroring, so WorldEdit `//rotate`, structure blocks and Create contraptions turn the sculpture along with the block.

## 7. FAQ and limitations

**Why can't I configure anything?**
You need an implanted Netlink Terminal. Bugs, Wall Extenders and Advanced Elevator Pulleys are configured only with **HUD vision on** (H). Advanced Redstone Links just need a plain right-click.

**"Not authorized on X's network"**
The device, keyboard or script belongs to someone else. Ask them for `/network authorize <you>`.

**My Wall Extender won't fold.**
- "Glue the shape first": the clicked block isn't glued to at least one other block.
- "Too big - a Wall Extender carries up to 4096 blocks".
- "*N* blocks in the shape have block entities and can't be folded": chests, signs, Create machines and similar can't be part of the shape.
- "fill the *N* red plate spots with solid blocks": plates are built into existing full solid blocks on the chosen side.

**My script says "script timed out".**
A loop ran too long without yielding. Add `task.wait()` inside long loops (limits are in [Limits](#limits)).

**`world` is nil in my script.**
The network owner wasn't an operator when the script started. Make them an operator and press **Run** again.

**`lift:GetFloors()` is empty / `lift:GoTo` does nothing.**
The cabin isn't assembled or the pulley's chunk isn't loaded. An elevator in an unloaded chunk still exists for scripts, with `Assembled = false`. Wait for `lift.Assembled` before reading floors.

**`lift:GoTo(2)` went to the wrong floor.**
Floors are matched by name before number. Unnamed contacts are named `0, 1, 2…` from the bottom, while the 1-based number is only used when no name or label matches. Give your contacts short names, or pass the name from `GetFloors()`.

**My toggled keyboard channel switched off when I pressed Release on the map.**
Keyboard **Toggle** and map **Hold/Release** use the same latch.

**Does anything work across dimensions?**
Yes. Channels are per network, not per dimension. Devices still need their chunk loaded to act.

**Other limits at a glance**

| Thing | Limit |
|---|---|
| Wall Extender shape | 2–4096 glued blocks, no block entities; speed 1–100 ticks per block |
| Netlink Glue auto-glue | 24 blocks per axis, 8192 blocks; natural terrain skipped |
| Netlink Glue selection | at most 4096 glue pieces (16-block tiles) |
| Keyboard | 48 binds; pulse ticks 1–1200 |
| Channel name | 64 characters |
| HUD range | 64 blocks |
| Scripts | 32 per network, 60,000 characters each |
| Storage | 2000 keys per network |
| Voxel sculpture | 64 voxels per edge, 255 materials per block |
